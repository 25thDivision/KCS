## 4. 결론

**sim LER로 ranking하면 hw LER 대비 inversion이 사라진다.** 유효 6개 hw config 전체에서 ρ(simLER, hwLER) = 0.88~0.98 (평균 0.931, 모두 p<0.006)로 simulation LER 순위가 하드웨어 순위를 거의 완벽히 예측한다. 반면 동일 비교축에서 sim ECR 성능순위는 hw LER와 평균 ρ = -0.421로 음의 상관(=논문에서 관찰된 rank inversion)을 보이고, simulation 내부에서도 ECR 순위와 LER 순위는 평균 ρ = -0.282로 불일치한다. 즉, 논문의 sim-hw rank inversion은 sim-to-real gap이 아니라 **ECR metric 자체의 특성**이 주 원인이다. 재-inference 감사(appnp_gcnii_allones_audit.csv) 결과 APPNP/GCNII는 45개 config 전부에서 입력과 거의 무관한 **상수 mask로 붕괴** (대표 config들에서 10^5 shot 중 unique mask 1개, frac_ones 0.12~0.79). 상수 mask는 ECR로는 대략 mask 밀도만큼(평균 APPNP 57%, GCNII 46% — Table I의 ~50%대와 정합) 점수를 받지만, LER로는 mask의 logical-support parity에 따라 NC(짝수) 또는 1−NC(홀수)로 발산하여 디코더로서 무의미함이 드러난다. 리뷰어 요청 관점에서: metric을 LER로 통일하면 simulation benchmark는 hardware 성능의 강력한 예측자가 된다.

## 5. 방법론 기록

- **재학습 없음**: `stim_simulation/saved_weights/<code>/<noise>/<model>/best_<model>_d<d>_p<p>_X.pth`의 `model_state_dict`만 로드하여 inference.
- **Threshold**: 기존 ECR 평가(run_stim_simulation.py)와 동일하게 `logits > 0` (sigmoid 0.5). 전처리 없음 — 저장된 test npz의 features를 그대로 사용 (uint8→float, 학습 코드와 동일).
- **LER 정의**: residual = pred XOR label(주입 오류 mask), logical flip = residual과 logical-Z support의 홀수 겹침. dataset에 observable flip이 저장되어 있지 않아 residual-parity 방식만 가능 (두 방식 교차검증은 불가).
- **Logical-Z support** (hw 파이프라인 정의 재사용): surface = SurfaceCodeCircuit.logical_z(왼쪽 열), heavyhex d3 = [0,3,6], color d5 = [0,1,2,3,4]. **color d3는 sim(COLORCODE_FACES)과 hw(STEANE_CODE)의 face 정의가 달라** face-membership 매칭으로 유일 relabeling π(sim→hw)=[4,1,0,2,3,5,6]을 계산해 hw logical_z [0,1,4]를 sim 라벨링 [0,1,2]로 pull-back했다 (commutation 런타임 검증 포함). 이 항목만 자체 유도가 개입된 판단 지점.
- **MWPM**: 마지막 라운드 cumulative Z-syndrome을 hw 계열 디코더로 decode (heavyhex: MWPMHeavyHexDecoder, color: MWPMColorCodeDecoder(+π), surface: pymatching.Matching(H_z)). MWPM_mv는 라운드별 raw Z-syndrome majority vote 후 동일 decode.
- **Sanity**: NoCorrection LER는 모든 config에서 해석값 (1−(1−2p)^|L|)/2와 일치(±shot noise), graph/image 독립 test set 간에도 일치. zero-correction 경로가 NC parity와 bit-exact 일치함을 확인.
- **batch size 256** (OOM 없음, GraphTransformer d5 포함), GPU: RTX 2080 Ti (cuda:1), 총 inference 소요 약 13분 (surface ~8분 + color/heavyhex ~5분), test shots: config당 10^5.

## 6. 한계 (해석 시 주의)

- **Label은 주입된 IID X 오류만 기록**하고 회로 노이즈(gate depol gd, data depol dp)가 만드는 실제 데이터 오류는 포함하지 않는다. 따라서 sim LER는 '주입 성분 기준 LER'이며, syndrome을 물리적으로 올바르게 설명하는 MWPM은 label에 없는 실제 오류까지 정정하여 불리해진다 (MWPM > NoCorrection이 나오는 이유; 예: dp0.005/gd0.015 프로파일에서 큐빗당 회로 유발 X-오류율 ~9%). ML 모델 8개는 모두 동일 convention으로 학습·평가되므로 **ML 간 상대 순위에는 영향 없음**. MWPM 행은 절대값 비교가 아닌 참고용.
- ECR과 (1−LER)은 다른 양이며 실제로 일치하지 않음을 확인 (버그 아님).
- ibm_pittsburgh d3는 hw standalone spread가 shot-noise 이하라 ρ 해석에서 제외 (표에는 참고용 포함; 참고로 ρ=0.87로 다른 config와 같은 방향).
